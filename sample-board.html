4.71

Vantage SSO gateway zero-day exploited to mint long-lived session tokens

Ridgeline Security Wire 3h ago 6 min readzero-dayexploitidentity
extract_insights

Summary

Ridgeline reports active exploitation of a token-forging flaw in Vantage identity gateways, with a vendor patch now available.

Ideas

  • The flaw is in token issuance, not token validation, so refreshing signing keys does not evict an attacker who already minted credentials.
  • Session lifetime is doing more security work in most environments than anyone intended, and nobody owns that setting.
  • Detection lands on session anomalies rather than the exploit itself, which means identity telemetry is the only reliable signal here.
  • Organizations that log token issuance separately from authentication events found this faster than organizations that log only logins.
  • The seven-day remediation window in the advisory is shorter than the average change window at mid-market companies, which is the real operational story.

Insights

  • Patching closes the door but does not evict anyone already inside; credential revocation is a separate, often unrehearsed procedure.
  • Identity infrastructure sits outside most patch SLAs because it is classified as a platform rather than an application.

Recommendations

  • Inventory every gateway version and confirm token signing key rotation is part of the response, not just the upgrade.
  • Rehearse mass session revocation before you need it, and time how long it takes end to end.
  • Add token issuance volume to the alerting baseline so anomalies surface without a signature.

Ransomware crew pivots from phishing to poisoning shared build pipelines

Ridgeline Security Wire 16h ago 9 min readransomwaresupply chain
extract_insights

Summary

A ransomware group reached forty downstream vendors by compromising one shared build pipeline and inserting an unsigned artifact.

Ideas

  • The economics changed: one pipeline compromise now yields better returns than forty phishing campaigns.
  • Unsigned build artifacts remain common in internal pipelines because signing is treated as a release-time control rather than a build-time one.
  • Downstream vendors detected the compromise through dependency drift, not through malware signatures.

Recommendations

  • Treat build systems as production identity infrastructure and apply the same access review cadence.
  • Require artifact signing at build time, and fail closed when a signature is missing.

3.40

Budgeting context windows for agent loops on CPU-only hardware

Practical Inference 6h ago 14 min readagentquantization
extract_wisdom

Summary

A practical guide to running agent loops on commodity CPUs, covering quantization tradeoffs, prompt caching, and model residency.

Ideas

  • On CPU, time to first token is dominated by model load, so keeping a model resident matters more than raw quantization level.
  • Q4 quantization holds up well for summarization and extraction, and degrades noticeably on multi-step arithmetic.
  • Context window size is a memory decision before it is a quality decision; oversized windows slow every request in the loop.
  • Batching several short pattern runs against one resident model beats running one large synthesis pass.
  • Reasoning models emit substantial hidden output that you pay for in latency even when you discard it.

Insights

  • The right unit of optimization for a local pipeline is the run, not the request. Keep the model warm and let the queue do the work.

Recommendations

  • Set keep-alive long enough to span an entire batch run rather than a single call.
  • Measure tokens per second at your actual context size, not at the default.
